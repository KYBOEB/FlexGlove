# FlexGlove — носимый интерфейс телеуправления на гибких сенсорах

Учебный проект ТПУ (проектная деятельность, осень 2026). Гибкие AgNW-сенсоры на пальцах → ESP32 →
Bluetooth → ПК-приложение: фильтры, калибровка, 3D-рука и **обучаемые статические жесты → локальные аудиофразы**.
Разработка и показ работают на демо без ожидания прошивки. Звук воспроизводит Python через устройство компьютера.

| Часть | Папка | Ответственный |
|---|---|---|
| Сенсоры и схема | `hardware/` (появится) | Лиза |
| Прошивка ESP32 | `firmware/` | Захар |
| ПК-приложение (обработка сигналов, контроллер, интерфейс) | `host/` | Данила |
| Документация, решения, план | `docs/` | все |

## Запуск на Windows

1. Нужен Python 3.10+ ([python.org](https://www.python.org/downloads/), при установке отметить «Add python.exe to PATH»).
2. Двойной щелчок по **`FlexGlove.pyw`**.
   Первый раз появится окно «FlexGlove готовится к первому запуску» (1–2 минуты): создаётся окружение,
   пакеты ставятся из папки `wheels/` без интернета, на рабочем столе и в «Пуске» появляется ярлык **FlexGlove**.
3. Дальше запускайте ярлыком. Приложение работает **без консоли**: интерфейс открывается во вкладке
   **браузера по умолчанию**, рядом с часами — значок FlexGlove (меню: открыть, папка с записями, журнал, выход).
   Повторный запуск при открытом приложении просто открывает вкладку.

Если `.pyw` открывается не Python'ом: правый щелчок → «Открыть с помощью» → Python.
Для отладки с выводом сообщений сервера — `tools\windows\FlexGlove-console.bat`.

**macOS / Linux / разработка:**
```bash
python3 FlexGlove.pyw                      # то же самое, что на Windows
# или вручную:
cd host && python -m venv .venv && source .venv/bin/activate
pip install -r ../requirements-dev.txt
python -m flexglove --demo                 # консольный запуск; --ui app — окно Edge/Chrome
```

## Что умеет v0.8.1

**Жест → аудиофраза:** на экране «Жесты» покажите позу, нажмите «Создать жест», введите название и держите пальцы
неподвижно около секунды и нажмите «Записать жест». В окне видна текущая поза той же 3D-руки.
После обучения миниатюра показывает сохранённый эталон; она доступна для просмотра и после перезапуска,
включая ранее созданные жесты. Ракурс фиксирован, ориентация не используется при распознавании.
Здесь же назначьте один из своих MP3 из папки `audio/` рядом с `FlexGlove.pyw`.
Выйдите из позы, затем покажите её снова: 700 мс устойчивого совпадения → одна фраза. Для повтора нужен
уверенный выход на 350 мс; можно перейти сразу к другому жесту. Несколько вкладок не дублируют звук.
Отсутствующий файл показывается как «аудио не назначено/недоступно». Есть проверка аудио и остановка очереди.

Эталоны непрерывных сгибов сохраняются в SQLite, переименовываются, переобучаются и удаляются.
Профили демо и перчатки разделены. Обучение требует фиксированной шкалы: ручная калибровка всех доступных
каналов или известные диапазоны демо. Изменение каналов/соответствия/калибровки требует проверки совместимости
и переобучения. Неизвестные и неоднозначные позы не вызывают фразу. Старые настройки команд остаются в базе,
но их распознавание отключено. Пошаговый показ, пороги и границы проверки — [docs/gesture-audio.md](docs/gesture-audio.md).

**Рука** — большая 3D-рука, текущее название уверенного кандидата или «Покажите жест».
Полоса удержания берёт значение из распознавателя и скрыта без подходящего кандидата.
Последнее срабатывание не подменяет текущую позу. Отсутствие источника, устаревание потока,
необходимость калибровки или обучения показаны явно. Есть компактное состояние связи,
вращение мышью, «Обнулить поворот», «Вид по умолчанию» и запасной 2D-силуэт.
Демо-панель видна только для демо. Ориентация кисти не входит в признаки жестов.

**Жесты** — создание, обучение, переименование, переобучение, удаление, назначение MP3,
проверка звука и остановка с очисткой очереди. Список, действия и результат воспроизведения
разделены. При отсутствии файла или ошибке устройства показана причина.

**Сигналы** — графики («сгиб, %» или «сырые АЦП»), показания пальцев и IMU, диагностика,
журнал, запись CSV, запись по протоколу с подсказками и воспроизведение CSV.
Раздел «Обработка» изначально закрыт. Смена пресета или применение JSON требует подтверждения:
сохранённые жесты станут несовместимыми и потребуют переобучения. Открытие раздела и выбор
«Свой конвейер» сами по себе обработку не меняют.
Разбор записи: `python tools/analyze_recording.py data/recordings/<файл>.csv`.

**Настройки** — подключение Bluetooth LE, порт USB / BT Classic, демо на 2 или 5 сенсоров,
соответствие каналов пальцам, выбор руки, мастер калибровки «ладонь → кулак → итог» и
параметры крепления MPU6050. «Обнулить поворот» меняет направление, наклоны остаются
абсолютными по гравитации.

**Приём данных** — сырые значения АЦП (основной формат: `213;215;210;220;218`), по одному сенсору, с метками
(`S1:213`), отдельные BLE-характеристики на сенсор, бинарно, старые биты `01`, а также протокол v0.3 с MPU6050
(`213;300|12;-4;998;5;-12;3`). См. [docs/protocol.md](docs/protocol.md).

**Обработка канала** — конвейер фильтров (пресеты «Базовый», «One-Euro», «Сильное сглаживание» или свой JSON —
«Сигналы → Обработка») → калибровка (ручная или автоматическая) → сгиб 0…1 → согнут/разогнут с гистерезисом. Блоки фильтров,
распознаватели и ориентация по IMU — в модуле `dsp/` ([docs/dsp.md](docs/dsp.md)). Сравнить конвейеры на записи:
`python tools/evaluate.py data/recordings/<файл>.csv --compare one_euro smooth`.

## Подключение перчатки
1. **Bluetooth LE** (ESP32-S3 — только BLE): «Настройки → Найти устройства → Подключить». Приложение подписывается
   на все notify-характеристики, UUID знать не нужно. Сопрягать перчатку в настройках Windows не нужно.
2. **Порт**: USB-кабель или Bluetooth Classic (на Windows — исходящий из двух COM-портов «Стандартный последовательный
   порт по Bluetooth»). Одна строка — одно сообщение.
3. **Демо**: реалистичная имитация 5 сенсоров; пальцы сгибаются щелчком по силуэту или клавишами 1–5.
4. **Файл**: «Сигналы → Открыть CSV…» — воспроизводит запись через ту же обработку.

## Структура
```
FlexGlove.pyw          запуск двойным щелчком (первая установка + ярлыки)
host/flexglove/
  desktop.py           запуск без консоли: сервер + браузер + значок в трее
  __main__.py          консольный запуск (python -m flexglove)
  app.py               REST /api/* и WebSocket /ws
  engine.py            ядро: каналы, обучаемые жесты, калибровка, запись
  gestures.py          эталоны, совместимость, RMS и временной автомат
  audio.py             Python MP3-проигрыватель, отдельный поток, ограниченная очередь
  processing.py        канал целиком: конвейер фильтров → калибровка → сгиб → 0/1
  dsp/                 фильтры-блоки и пресеты, калибровка, признаки, покой/движение, распознаватели, ориентация IMU
  commands.py          архивный алгоритм команд D-21 (в ядре не выполняется)
  imu.py               ориентация кисти: оси руки, смещение гироскопа, Madgwick, обнуление
  control.py           безопасный контроллер захвата (сжатие и поворот)
  parser.py            разбор сообщений (все форматы)
  recording.py         запись CSV
  sources/             ble.py, serial_src.py, mock.py, replay.py
  calib_wizard.py      мастер калибровки: замеры «ладонь» / «кулак», оценка каналов
  web/                 интерфейс: index.html, app.js, hand3d.js (3D-рука), handpose.js (сгиб → углы суставов),
                       hand.js (2D), chart.js, style.css; vendor/three (three.js r170 + GLTFLoader, OrbitControls, MIT),
                       vendor/models/generic-hand (модель руки WebXR, MIT)
host/tests/            pytest (+ data/ — реальная запись с ESP32)
firmware/examples/     эталонный скетч ESP32: 5 значений АЦП по BLE
tools/                 офлайн-оценка фильтров (evaluate.py) и ориентации (evaluate_imu.py), разбор записи (analyze_recording.py), сборка Windows-архива
docs/                  протокол, архитектура, решения, план, анализ данных, материалы для Claude
audio/                 свои MP3 (не в git), инструкция
data/                  база настроек/эталонов, записи, журнал (не в git)
```

## Разработка
```bash
cd host
python -m pytest -q
```
- ветка на этап/задачу (`stage-2-prototype`), в `main` — через pull request; коммиты `host: …`, `firmware: …`, `docs: …`;
- формат обмена меняется только вместе с [docs/protocol.md](docs/protocol.md);
- демо-режим должен работать всегда — это среда разработки и резерв на защите;
- сборка архива для Windows с офлайн-пакетами: `python tools/make_windows_bundle.py`.
