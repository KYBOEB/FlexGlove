# FlexGlove — носимый интерфейс телеуправления на гибких сенсорах

Учебный проект ТПУ (проектная деятельность, осень 2026). Гибкие AgNW-сенсоры на пальцах → ESP32 → Bluetooth →
ПК-приложение, которое обрабатывает сигналы, показывает руку оператора и управляет **виртуальным захватом**
через безопасный контроллер команд. Жесты-комбинации пальцев — дискретные команды оператора.

| Часть | Папка | Ответственный |
|---|---|---|
| Сенсоры и схема | `hardware/` (появится) | Лиза |
| Прошивка ESP32 | `firmware/` | Захар |
| ПК-приложение (обработка сигналов, контроллер, интерфейс) | `host/` | Данила |
| Документация, решения, план | `docs/` | все |

## Запуск на Windows

1. Нужен Python 3.10+ ([python.org](https://www.python.org/downloads/), при установке отметить «Add python.exe to PATH»).
2. Двойной щелчок по **`FlexGlove.pyw`**.
   Первый раз появится окно «FlexGlove готовится к первому запуску» (1–2 минуты): создаётся окружение,
   пакеты ставятся из папки `wheels/` без интернета, на рабочем столе и в «Пуске» появляется ярлык **FlexGlove**.
3. Дальше запускайте ярлыком. Приложение работает **без консоли**: интерфейс открывается во вкладке
   **браузера по умолчанию**, рядом с часами — значок FlexGlove (меню: открыть, папка с записями, журнал, выход).
   Повторный запуск при открытом приложении просто открывает вкладку.

Если `.pyw` открывается не Python'ом: правый щелчок → «Открыть с помощью» → Python.
Для отладки с выводом сообщений сервера — `tools\windows\FlexGlove-console.bat`.

**macOS / Linux / разработка:**
```bash
python3 FlexGlove.pyw                      # то же самое, что на Windows
# или вручную:
cd host && python -m venv .venv && source .venv/bin/activate
pip install -r ../requirements-dev.txt
python -m flexglove --demo                 # консольный запуск; --ui app — окно Edge/Chrome
```

## Что умеет v0.5.0

**Пульт** — 3D-модель руки оператора (сгиб каждого пальца и ориентация кисти по MPU6050; без WebGL — 2D-силуэт),
«Обнулить положение» и калибровка гироскопа, поворот захвата креном кисти, виртуальная «горячая камера» с захватом и образцом,
контроллер команд: сжатие кисти → команда захвату с ограничениями, кнопки и жесты «Управление (ARM)»,
«Фиксация захвата», «Подсветка», журнал событий.

**Сигналы** — графики всех каналов (сырые + обработанные), калибровка «ладонь раскрыта / кулак сжат»,
запись в CSV (формат Excel, как у программы Захара), **запись по протоколу** с подсказками (покой → 5 сгибов → покой),
воспроизведение любой записи CSV. Разбор записи: `python tools/analyze_recording.py data/recordings/<файл>.csv`.

**Настройки** — подключение (Bluetooth LE с автопереподключением, порт USB / BT Classic, демо на 2 или 5 сенсоров),
отладка потока с предупреждениями (низкая частота, «молчащий» канал), какой канал на каком пальце и его роль
(«сжатие» — ведёт захват, «команды» — участвует в жестах), все комбинации пальцев с мини-силуэтами и привязка команд.

**Команды не мешают сжатию (D-21)** — пока управление активно, пальцы сжатия исключаются из жестов, команда
срабатывает удержанием ≥ 1 с и только если пальцы сжатия неподвижны: сжатый кулак не переключает команды.

**Приём данных** — сырые значения АЦП (основной формат: `213;215;210;220;218`), по одному сенсору, с метками
(`S1:213`), отдельные BLE-характеристики на сенсор, бинарно, старые биты `01`, а также протокол v0.3 с MPU6050
(`213;300|12;-4;998;5;-12;3`). См. [docs/protocol.md](docs/protocol.md).

**Обработка канала** — конвейер фильтров (пресеты «Базовый», «One-Euro», «Сильное сглаживание» или свой JSON на вкладке
«Сигналы») → калибровка (ручная или автоматическая) → сгиб 0…1 → согнут/разогнут с гистерезисом. Блоки фильтров,
распознаватели и ориентация по IMU — в модуле `dsp/` ([docs/dsp.md](docs/dsp.md)). Сравнить конвейеры на записи:
`python tools/evaluate.py data/recordings/<файл>.csv --compare one_euro smooth`.

## Подключение перчатки
1. **Bluetooth LE** (ESP32-S3 — только BLE): «Настройки → Найти устройства → Подключить». Приложение подписывается
   на все notify-характеристики, UUID знать не нужно. Сопрягать перчатку в настройках Windows не нужно.
2. **Порт**: USB-кабель или Bluetooth Classic (на Windows — исходящий из двух COM-портов «Стандартный последовательный
   порт по Bluetooth»). Одна строка — одно сообщение.
3. **Демо**: реалистичная имитация 5 сенсоров; пальцы сгибаются щелчком по силуэту или клавишами 1–5.
4. **Файл**: «Сигналы → Открыть CSV…» — воспроизводит запись через ту же обработку.

## Структура
```
FlexGlove.pyw          запуск двойным щелчком (первая установка + ярлыки)
host/flexglove/
  desktop.py           запуск без консоли: сервер + браузер + значок в трее
  __main__.py          консольный запуск (python -m flexglove)
  app.py               REST /api/* и WebSocket /ws
  engine.py            ядро: каналы, жесты-команды, калибровка, запись
  processing.py        канал целиком: конвейер фильтров → калибровка → сгиб → 0/1
  dsp/                 фильтры-блоки и пресеты, калибровка, признаки, покой/движение, распознаватели, ориентация IMU
  commands.py          жесты-команды: роли пальцев, удержание, защита от сжатия (D-21)
  imu.py               ориентация кисти: оси руки, смещение гироскопа, Madgwick, обнуление
  control.py           безопасный контроллер захвата (сжатие и поворот)
  parser.py            разбор сообщений (все форматы)
  recording.py         запись CSV
  sources/             ble.py, serial_src.py, mock.py, replay.py
  web/                 интерфейс: index.html, app.js, hand3d.js (3D-рука), hand.js (2D), chart.js, style.css,
                       vendor/three (three.js r170, MIT)
host/tests/            pytest (+ data/ — реальная запись с ESP32)
firmware/examples/     эталонный скетч ESP32: 5 значений АЦП по BLE
tools/                 офлайн-оценка фильтров (evaluate.py) и ориентации (evaluate_imu.py), разбор записи (analyze_recording.py), сборка Windows-архива
docs/                  протокол, архитектура, решения, план, анализ данных, материалы для Claude
data/                  база настроек, записи, журнал (не в git)
```

## Разработка
```bash
cd host
python -m pytest -q
```
- ветка на этап/задачу (`stage-2-prototype`), в `main` — через pull request; коммиты `host: …`, `firmware: …`, `docs: …`;
- формат обмена меняется только вместе с [docs/protocol.md](docs/protocol.md);
- демо-режим должен работать всегда — это среда разработки и резерв на защите;
- сборка архива для Windows с офлайн-пакетами: `python tools/make_windows_bundle.py`.
