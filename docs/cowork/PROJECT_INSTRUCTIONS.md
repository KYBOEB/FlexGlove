# Инструкции проекта Cowork «FlexGlove»

> Этот текст целиком вставляется в поле **инструкций проекта** в Cowork.

## Контекст
Учебный проект ТПУ (проектная деятельность, осень 2026, защита до 25.12.2026): **носимый интерфейс телеуправления**
на гибких AgNW-сенсорах. Сенсоры на пальцах → ESP32 (BLE, сырые значения АЦП, 50 Гц) → ПК-приложение: обработка
сигналов, силуэт руки, безопасный контроллер команд → виртуальный захват (позже — реальный); жесты-комбинации пальцев —
дискретные команды оператора. Направление выбрано командой 25.10 (продукт 2 из аналитики; продукт 1 «цифровой
наставник» использует ту же платформу записи и датасетов).

Команда: **Лиза** — гибкие сенсоры и схема; **Захар** — прошивка ESP32 и передача по Bluetooth;
**Данила** (пользователь, с которым ты работаешь) — ПК-приложение: backend, обработка сигналов, ML, интерфейс.

## Источники истины (читать в начале каждого чата)
Репозиторий `flexglove` (папка подключается к чату):

## Как устроена работа
- Один чат = один этап (или крупная задача). Чат начинается с промпта из `docs/cowork/STAGE_KICKOFF.md`.
- Отдельный чат-«планировщик» ведёт план и анализирует результаты; этапные чаты его не заменяют.
- В конце этапа чат выдаёт **отчёт по шаблону** `docs/cowork/STAGE_REPORT_TEMPLATE.md` текстом в чат —
  пользователь переносит его в планировщик.

## Технические правила
- Основная платформа — **Windows 10/11**: запуск `FlexGlove.pyw` / ярлык (без консоли, браузер по умолчанию, значок в трее); macOS/Linux должны продолжать работать.
- Python 3.10+, FastAPI, bleak, pyserial, SQLite, pystray (трей, Windows); интерфейс — HTML/JS без сборщика и без CDN (`host/flexglove/web`).
- Безопасность: команды захвату — только через `control.py`; не обещать в документах замену аппаратной аварийной остановки.
- Пути — через `pathlib`, никаких POSIX-специфичных вещей в основном коде; `.bat` — с окончаниями строк CRLF.
- Всё в одном цикле asyncio; блокирующие операции — в потоках (`asyncio.to_thread`).
- Демо-режим (`python -m flexglove --demo`) должен работать после любого изменения — это среда разработки и резерв на защите.
- Новый код — с тестами pytest (`cd host && python -m pytest -q`); перед завершением этапа все тесты зелёные.
- Формат обмена меняется только вместе с `docs/protocol.md`; совместимость со старым форматом сохраняется, пока прошивка не обновлена.
- Новое решение архитектурного уровня — строка в `docs/decisions.md`; изменения версии — в `CHANGELOG.md`.
- Работа в ветке `stage-N-краткое-имя`, коммиты небольшие, сообщения на русском с префиксом части: `host:`, `firmware:`, `docs:`.
- Интерфейс, комментарии и документация — на русском. Имена в коде — на английском.
