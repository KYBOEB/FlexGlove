первым коммитом этапа их нужно перенести в `docs/`.

Текущий этап: **4б** (показ команде 08.11). После него — **2б** (сессия с реальными сенсорами Захара).

## Этап 4б — 3D-рука на весь экран, понятные данные

```
Этап 4б: большая реалистичная 3D-рука на главном экране, понятная калибровка и отображение пальцев.
Ветка stage-4b-hand от main (если stage-4-imu-3d ещё не слита в main — слей первым шагом, тесты до и после).
Показ команде — завтра, поэтому строго по приоритетам: сначала P0, потом P1.

Контекст от планировщика:
- Захар подключил реальные сенсоры к приложению. Отзывы: непонятно, как работает калибровка; графики «кривые»;
  непонятен формат 11111 у пальцев; миниатюра с роботом и образцом не нужна; нужна нормальная 3D-рука, которая
  вертится по гироскопу и повторяет жесты перчатки.
- Планировщик запустил v0.5.0 в демо: 3D-рука есть, но маленькая (карточка ~220 px) и грубая (ладонь-коробка,
  пальцы-цилиндры). У Данилы её вообще не было видно: браузер взял из кэша старые app.js/style.css к новому index.html.
- Сейчас при подключении «обнуляется» вся поза — если перчатку подключили с опущенной рукой, модель покажет пальцы
  вверх. Нужна абсолютная ориентация по гравитации.
- Решения D-26…D-29 (предложены планировщиком) — в документах проекта Claude, docs/decisions.md.

   host/flexglove/imu.py, web/hand3d.js, web/index.html, web/app.js. Перенеси из документов проекта Claude
   актуальные roadmap.md, decisions.md, cowork/STAGE_KICKOFF.md в docs/.

2. P0 — к завтрашнему показу:
   a. Кэш: /static отдаётся с Cache-Control: no-cache; в index.html ссылки на js/css/модули с ?v=<версия>.
      Проверка: поменять файл → обычное обновление страницы показывает изменение.
   b. Убрать из интерфейса «Рабочую зону» (робот, образец, поворот захвата) и карточку «Контроллер команд».
      Код control.py и команд в ядре не удалять (тесты остаются) — только не показывать. D-26.
   c. Главный экран «Рука»: 3D-рука занимает основную часть окна (≈ 70–75 % ширины, на всю высоту под шапкой).
      Справа узкая панель: пальцы (п. 3a), распознанный жест словами, связь и IMU, кнопки «Калибровка»,
      «Обнулить поворот», «Вид по умолчанию».
   d. Реалистичная модель вместо примитивов — анатомическая рука со скелетом (glTF). Предпочтительно generic-hand
      из @webxr-input-profiles/assets (MIT, кости по стандарту WebXR: wrist, *-metacarpal, *-phalanx-proximal /
      intermediate / distal, *-tip) — скачать один раз в web/vendor/models/ вместе с лицензией; GLTFLoader (с его
      зависимостями) и OrbitControls из three r170 examples/jsm — тоже в vendor, без CDN в работе. Если модель
      не подходит — предложи другую с открытой лицензией (CC0 / CC-BY / MIT) и согласуй со мной.
      Вид по референсу docs/background/hand_reference.png: белый матовый материал, мягкий свет, светло-серый фон,
      мягкая тень. Правая/левая — по настройке.
      Сгиб пальца 0..1 → повороты костей: проксимальная до 80–90°, средняя до 100°, дистальная ≈ 2/3 средней;
      большой палец — своя ось и пределы. Пальцы без сенсора — нейтральная поза, светлее/полупрозрачные.
      Мышью — вращение вида (OrbitControls), кнопка «Вид по умолчанию». Если WebGL недоступен — 2D-силуэт.
   e. Ориентация как у настоящей руки (D-28): крен и тангаж — абсолютные по гравитации (рука опущена → модель
      пальцами вниз; ладонь вверх → модель ладонью вверх). «Обнулить поворот» и автообнуление при подключении
      касаются только рысканья. Камера неподвижна в мировых координатах (верх экрана = верх комнаты).
      Тесты на синтетике для 4 поз: пальцы вверх, пальцы вниз, вперёд ладонью вниз, вперёд ладонью вверх.
   f. Демо: ползунки крена / тангажа / рысканья и режим «обзор» (плавные движения кисти и пальцев) — рука на
      экране выглядит живой без железа.

3. P1 — понятные данные (после P0; если успеваешь — до показа):
   a. Пальцы вместо 11111: для каждого пальца строка — название, полоса «сгиб 0–100 %», состояние словами
      (разогнут / полусогнут / согнут), мелко — сырое значение и «Δ от ладони» (сырое − уровень «ладонь раскрыта»).
      Комбинации в интерфейсе — словами и мини-силуэтом («указательный + средний»); двоичная строка остаётся
      только в «Отладке потока».
   b. Калибровка — мастер из 3 шагов с обратным отсчётом и картинкой позы: «раскройте ладонь — держите 3 с» →
      «сожмите кулак — 3 с» → итог по каждому каналу: уровни ладонь/кулак, размах, шум, оценка (хорошо /
      слабый сигнал / не меняется — проверьте сенсор), кнопки «Сохранить» / «Повторить». Автокалибровка — только
      как подсказка «нужна калибровка». Статус калибровки виден на главном экране.
   c. Графики: по умолчанию «сгиб 0–100 %» с общей фиксированной шкалой (без автомасштаба, который раздувает шум
      в «кривые» линии); переключатель «сырые АЦП» — шкала от уровня «ладонь» до «кулак» с запасом, без калибровки —
      фактический диапазон, но не уже 200 ед.; подписи осей и единицы.
   d. Выбор пресета фильтрации убрать с «Сигналов» в «Настройки → Дополнительно»; по умолчанию — пресет из D-23.

6. Критерий готовности: большая реалистичная белая 3D-рука на главном экране плавно повторяет наклоны (абсолютно
```
