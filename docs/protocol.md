# Протокол обмена ESP32 → ПК

ПК-приложение определяет формат **автоматически** (`host/flexglove/parser.py`), поэтому прошивка может
меняться постепенно. Что именно приходит — видно в «Настройки → Отладка потока».

## v0.2 — значения АЦП (основной формат, с 25.10)

Перчатка передаёт **сырые значения АЦП** каждого сенсора. Вся обработка (фильтр, калибровка, сгиб 0…1,
состояние 0/1) — на ПК. Так делает текущая программа Захара для одного сенсора (`sensor_data.csv`).

### Рекомендуемый вариант для 5 сенсоров — одна строка на отсчёт

```
213;215;210;220;218\n
```

- значения по порядку каналов S1…S5 (по умолчанию: большой, указательный, средний, безымянный, мизинец;
  соответствие меняется в «Настройки → Каналы и пальцы»);
- разделитель `;` (также принимаются `,`, пробел, табуляция);
- частота **50 Гц** (как сейчас), одно BLE-уведомление (notify) = одна строка;
- строка с 4-значными значениями длиннее 20 байт — в прошивке нужно `BLEDevice::setMTU(185);`
  (Windows договаривается о большем размере пакета автоматически). Если строки приходят обрезанными —
  перейти на бинарный вариант ниже.

### Другие варианты, которые приложение тоже понимает

| Как шлёт прошивка | Пример | Как понимает приложение |
|---|---|---|
| один сенсор, число текстом | `213` | 1 канал |
| у каждого сенсора своя notify-характеристика | `213` в каждой | канал = порядок характеристики |
| строки с метками | `S1:213`, `ch2=215`, `A0: 210` | канал = порядок меток (A0…A4, S1…S5 и т. п.) |
| бинарно, k × uint16 little-endian | 10 байт для 5 сенсоров | k каналов; самый компактный вариант |
| бинарно, одно int32 | `setValue(int)` | 1 канал |
| бинарный пакет v0.1 (ниже) | 19 байт | каналы + номер пакета + время устройства |
| строки, начинающиеся с `#` | `# debug` | пропускаются (отладочный вывод) |

### Чего не хватает в текущем потоке (анализ 25.10)
Время в записи — время **приёма на ПК**: из-за того, что BLE доставляет пакеты пачками, интервалы
скачут от 0 до 143 мс при среднем 20 мс. Для точных датасетов нужно **время устройства** (`millis()`)
и **номер пакета** — это даёт бинарный пакет v0.1. Подробности — [analysis/2026-10-25-sensor-stream.md](analysis/2026-10-25-sensor-stream.md).

## v0.3 — гибкие сенсоры + MPU6050 (черновик, согласовать с Захаром до этапа 4)

Одна строка = один синхронный отсчёт, 50 Гц, одно BLE-уведомление:

```
213;300|12;-4;998;5;-12;3\n
```

- до `|` — значения АЦП гибких сенсоров, как в v0.2 (сейчас 2, позже до 5);
- после `|` — MPU6050: `ax;ay;az` в **мг** (1 g = 1000) и `gx;gy;gz` в **десятых долях °/с** (123 = 12,3 °/с), целые числа;
- диапазоны MPU6050: акселерометр ±2 g, гироскоп ±500 °/с, встроенный фильтр (DLPF) ≈ 44 Гц, опрос датчика 100 Гц;
- оси — как напечатано на модуле; модуль крепится на тыльную сторону кисти, ось X — к пальцам (фото крепления — в `hardware/`);
- строка без `|` разбирается как v0.2 — совместимость сохраняется;
- длина строки до ~45 байт → в прошивке `BLEDevice::setMTU(185)`.

Ориентацию (кватернион) считает ПК — сырые данные нужны для датасетов (решение D-19).

**Поддержка в приложении (v0.3.0):** строка разбирается (`parser.py`, формат `text-values+imu`), IMU хранится в
состоянии, видна в «Отладке потока» и пишется в CSV шестью колонками `ax (mg)` … `gz (0.1 dps)`; воспроизведение
такой записи снова даёт строки v0.3. Строка, в которой есть `|` и другие разделители, но после `|` не ровно
6 чисел (например, обрезанная по MTU), **отбрасывается** и считается в «не распознано» — значения IMU никогда
не превращаются в лишние каналы. Строка вида `213|215` (только `|`) по-прежнему значит два канала (v0.2).

## v0.1 — бинарный пакет (целевой для точной записи)

### BLE-сервис

| Элемент | UUID | Свойства | Назначение |
|---|---|---|---|
| Сервис GLOVE | `6e7a0001-6c6f-7665-2d66-6c6578676c76` | — | реклама и поиск перчатки |
| DATA | `6e7a0002-6c6f-7665-2d66-6c6578676c76` | notify | поток пакетов |
| CONTROL | `6e7a0003-6c6f-7665-2d66-6c6578676c76` | write | команды с ПК (позже) |
| INFO | `6e7a0004-6c6f-7665-2d66-6c6578676c76` | read | JSON: версия прошивки, n_ch, частота |

Имя устройства: `FlexGlove-XX`. Приложение подписывается на все notify-характеристики, поэтому UUID
желательны, но не обязательны.

### Пакет DATA (little-endian), 9 + 2·n_ch байт

| Смещение | Тип | Поле | Описание |
|---|---|---|---|
| 0 | u8 | ver | = 1 |
| 1 | u8 | n_ch | число каналов |
| 2 | u16 | seq | номер пакета — потери |
| 4 | u32 | t_ms | время устройства, мс |
| 8 | u8 | bits | маска пальцев (можно 0 — приложение считает само) |
| 9 | u16 × n_ch | values | значения АЦП |

5 каналов — 19 байт: помещается в стандартный BLE-пакет без настройки MTU.

```c
typedef struct __attribute__((packed)) {
  uint8_t  ver;       // = 1
  uint8_t  n_ch;
  uint16_t seq;
  uint32_t t_ms;
  uint8_t  bits;
  uint16_t values[5];
} glove_packet_t;
```

## v0 — биты пальцев (этап 0, поддерживается для совместимости)

Строка из `0`/`1`, первый символ — канал 1: `00`, `01`, `10`, `11`. Если поток уже показал значения АЦП,
неоднозначные сообщения из одних 0/1 трактуются как значения.

## Правила изменения
1. Любое изменение формата — сначала правка этого файла и согласование в чате команды.
2. Несовместимое изменение бинарного пакета — новый номер `ver`.
3. Тест на новый формат — в `host/tests/test_parser.py`.
