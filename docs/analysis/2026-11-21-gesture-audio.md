# Отчёт планировщику: обучаемые статические жесты и локальные аудиофразы

Дата: 21.11.2026. Ветка: `stage-5-gesture-audio`. Версия: **0.7.0**.
База: актуальная `origin/main`, `7fe3f6c` (PR №6 уже слит). Исходная рабочая копия чистая.

1. Сделано: создание эталона по секундному устойчивому замеру непрерывных сгибов, SQLite,
   переименование/повторное обучение/удаление, совместимость каналов и фиксированной калибровки,
   отдельные профили demo/glove/replay. Старые настройки не удаляются; автомат ARM/hold/light отключён.
   Добавлен Python MP3-проигрыватель, ограниченная последовательная очередь и интерфейс назначения/проверки/остановки.

2. Архитектура: `gestures.py` — чистый автомат обучения/распознавания с передаваемым временем;
   `audio.py` — отдельный поток, один music stream, FIFO с дедупликацией и отменой;
   `engine.py` связывает события и очередь; `static_gestures` — новая таблица SQLite.
   Публичное состояние различает кандидата, удержание, событие и стадии аудиозадания.
   Формат обмена с прошивкой не менялся. Фильтры, запись, демо и 3D-рука сохранены.

3. Решения: D-35…D-38 в `docs/decisions.md`. RMS без ориентации и без сложной ML-модели;
   неизвестная поза при большой дистанции/малом отрыве; удержание 700 мс и выход 350 мс;
   запрет событий при обучении/калибровке/устаревании; после восстановления нужен выход из удержанной позы.
   Для MP3 выбран pygame-ce с официальной документацией и Windows wheels для Python 3.10–3.14.

4. Проверено: локальный Windows pytest — **276 passed, 1 skipped** (POSIX serial).
   Временные проверки новых сценариев используют виртуальные часы; аудиотесты — FakeDriver без динамиков.
   Проверены известные/неизвестные/похожие позы, короткое/достаточное/долгое удержание,
   шумовой/настоящий выход, повтор и A→B→C, отсутствующий/устаревший канал, смена профиля/калибровки,
   разрыв/восстановление связи, отсутствие MP3, ошибка проигрывателя, FIFO, отмена, ограничения пути и несколько клиентов.
   Синтетическая выборка: 300/300 известных примеров; это не показатель точности реальной перчатки.
   CI настроен на Ubuntu и Windows, включая импорт MP3-бэкенда без открытия аудиоустройства и синтаксис JS.
   Статус конкретного запуска необходимо смотреть по последнему коммиту PR.

   На живом демо через браузер проверены создание, переименование, распознавание, отсутствие файла,
   отсутствие повтора при вращении кисти, отсутствие старой таблицы/ролей команд; JS-ошибок не найдено.
   Проверены и просмотрены снимки 1366×768 и 1920×1080:
   [главный экран 1366](img/gesture-audio/hand-1366.png), [настройки 1366](img/gesture-audio/settings-1366.png),
   [главный экран 1920](img/gesture-audio/hand-1920.png), [настройки 1920](img/gesture-audio/settings-1920.png).
   Машинный результат — [results.json](img/gesture-audio/results.json), повторение — `tools/qa_gesture_audio.py`
   с отдельной тестовой базой. Пользовательская `data/flexglove.db` в QA не открывалась.

5. Риски: предварительные границы дистанции **0,12**, отрыва **0,06**, выхода **0,22**,
   стабильности (размах **0,10**, окно **160 мс**), свежести **200 мс**, разрыва **120 мс**,
   минимум **20** отсчётов за секунду. 700/350 мс — требование сценария, а не обученные параметры.
   Слишком похожие позы с малым числом каналов могут быть принципиально неразличимы.
   Выборочные результаты декодера видны в API; успешный FakeDriver не подтверждает слышимость.

6. Нужно от команды: реальные записи непрерывного потока Захара с составом/соответствием каналов,
   повторными позами и ручной калибровкой; проверка устойчивости сенсоров Лизы. От пользователя — три своих MP3.

7. Технический долг: пороги настроены на синтетике и демо, без аппаратного датасета;
   старый контроллер и совместимые REST-настройки остаются в коде, но отсутствуют в новом пользовательском сценарии.
   Офлайн-архив нужно пересобрать с wheel pygame-ce. Готовый Windows ZIP на этом этапе не выпускался.

8. Следующий этап: записать несколько повторов известных и неизвестных поз у нескольких людей,
   измерить ошибки/ложные срабатывания и задержку, подобрать пороги на отложенных данных.
   Добавить три настоящих MP3 и отдельно проверить через звуковое устройство содержание/слышимость каждого,
   порядок A→B→C, остановку и две вкладки. **Три пользовательские фразы не проверены: файлов нет.**
